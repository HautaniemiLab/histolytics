    Repository maintenance plan¶

    Refresh Histolytics in small, independently reviewable changes. Establish reliable tests and release installations before upgrading runtime dependencies. Preserve public APIs, checkpoints, spatial feature definitions, and scientific results.

    Current state — 19 October 2026¶

    Histolytics 0.3.0 was published on 19 October 2026 from tag v0.3.0, commit 6ff049a, after PRs 33–35 completed release preparation. The installation split, standalone analysis composition, focused Torch upgrade and validation-file cleanup milestone is complete. No remaining backlog item is a 0.3.0 release gate.

    Release workflow 39242826093 passed all 29 validation jobs and trusted publication, including all 20 supported archive/profile installation combinations. Both PyPI archive hashes matched the validated workflow artifacts. A fresh macOS ARM64/Python 3.12 CPU-analysis install from PyPI passed bundled-data, spatial-query and feature checks without Torch or NVIDIA packages. Documentation deployment and the live publication citation were verified. Routine CI remains 15 jobs; no new scopes or baselines were added.

    Segmentation requires Torch >=2.9.1,<3.0, following the upstream model package's major-version limit. The development lock retains Torch 2.9.1. Additional CPU checks passed on Torch 2.10.0 in a fresh Linux full-profile install and Torch 2.14.1 on macOS, including the existing published-checkpoint comparison.

    Remaining work — separate milestones¶

    • Python 3.13: await compatible upstream Numba/llvmlite requirements, then validate supported profiles before changing support claims. Do not override upstream pins.
    • CuPy/cuML processing: evaluate CPU/GPU correctness and end-to-end cost when GPU hardware is available before deciding what to simplify. Retain cuCIM; remove nothing solely because it is optional or unmeasured.
    • Dependencies/security: triage reachable advisories and choose one justified upgrade batch at a time. No blanket dependency refresh.
    • Model/WSI/GPU validation: address the documented upstream reader boundaries and add targeted checks only when a concrete change needs them. The current CPU checkpoint and reader checks do not validate every model, vendor format or GPU.

    Typing rollout, broad docstring conversion and notebook/quick-start audits remain deferred work, not an automatic next phase. Choose one bounded milestone before starting further implementation; do not reopen baseline collection or CI expansion.

    Installation and dependency audit¶

Analysis and segmentation install on macOS 3.12; Linux 3.10–3.12 analysis/full and Linux 3.12 segmentation/CUDA-analysis profiles are verified. NVIDIA extras have no compatible macOS installation. Validate complete profile installations rather than describing omitted-dependency environments as clean installations. Avoid claiming cross-platform support from partial installs. The historical Dependabot snapshot predates the Torch upgrade and is not a current alert count. The upgraded minimum excludes the previously recorded critical Torch advisory's affected range; broader reachability review and triage remain open.

    Evaluate CuPy processing and retain cuCIM¶

    Keep cuCIM, including its WSI slide-reading backend. Evaluate the CuPy image and feature-processing implementations separately. The maintainer reports that these paths significantly complicate the code without bringing runtime benefits; use representative measurements and correctness comparisons to decide which paths to remove or simplify. CuPy removal decisions remain pending evaluation.

    • [x] Inventory CuPy/cupyx processing in nuclear texture, intensity, and chromatin features, collagen extraction, and image/mask utilities. Include cuML image clustering in the evaluation against its existing CPU implementation.
    • [ ] Compare CPU and GPU paths on representative image sizes, object counts, and WSI workloads. Record hardware, warmup, synchronization, end-to-end runtime, peak memory, and transfer overhead. Include setup costs and repeated workloads.
    • [ ] Remove or simplify paths that add substantial complexity without a useful measured benefit. Record the evidence and decision for each implementation.
    • [ ] Preserve feature definitions, instance labels, coordinate units, and CPU results. Verify representative bundled-data outputs against the CPU baseline.
    • [ ] Resolve the public feature-analysis device arguments explicitly. Document and test any deprecation or removal of device="cuda", update callers, notebooks, docstrings, and tests together, and include migration notes.
    • [ ] Remove CuPy/cuML requirements only when the evaluated cleanup leaves no callers requiring them, and regenerate uv.lock. Retain cuCIM and verify its slide-reading backend; review platform-specific installation boundaries separately.
    • [ ] Verify clean CPU installations and the supported platform/Python matrix. Preserve PyTorch CUDA support for panoptic model inference and training.

    Keep this cleanup separate from numerical dependency upgrades so changes in feature values can be attributed and reviewed independently.

    See the CuPy evaluation for transfer boundaries, correctness risks, and initial CPU texture timings. GPU comparison and peak-memory evaluation remain open. The initial bundled-image run exposed texture label/zero-row bugs; the merged fix corrects those shared bookkeeping paths with regression cases before collecting the corrected CPU reference. No CuPy path has been removed.

    Readiness cleanup rule¶

    Keep only regression fixtures and short provenance/settings needed for reproducible checks. Completed verbose captures and audit/environment dumps belong in Git history or CI artifacts. Any future temporary validation tooling must be removed when its bounded task is verified; do not add permanent workflow options or reports by default. Preserve meaningful regression coverage when retiring scaffolding.

    PRs 22 and 33–35 are merged. Per-instance checkpoint mappings, migration notes, accurate Python support metadata, Google-style API rendering and the reviewed Torch range are included in published 0.3.0. This milestone is closed; future releases still need explicit publication authorization.
